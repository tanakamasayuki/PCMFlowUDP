# EspToEspRaw

> English: [README.md](README.md)

UDPで生PCMのバイト列を交換するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [EspToEspRaw.ino](EspToEspRaw.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<WiFi.h>`, `<WiFiUdp.h>`, `<PCMFlow.h>`, `<PCMFlowUDP.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

UDPで生PCMのバイト列を交換する例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `g_udp.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `g_sink.flush(...)` — 対象機能の規則に従って保留分を完了／転送します。即時に戻るとは限りません。
3. `g_stream.poll(...)` — 保留入力を定期的に処理し、結果を確認してから新しい値を使います。

変更する前に確認する定数: `kPeerIp`, `kPort`, `kSampleRate`, `kFramesPerChunk`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

ローカルWi-Fi情報と相手のIP／ポートを設定します。UDP Socketを開始してからプロトコルの送受信を始め、受信は定期的にpollします。Raw UDP・VBAN・RTPは区切りや形式が異なるので双方を合わせます。

UDPに配送・順序・再送の保証はなく、送信結果は再生確認ではありません。これらの例にはマイク／スピーカーの仮実装があるため、無音の送信や受信byte数だけでは実音声を確認できません。サンプル／バイトの単位と送信間隔を保って実機入出力へ置き換えます。

RTP時刻はPayloadのクロックに従い、全コーデックがPCMの周波数と同じとは限りません（G.722など）。Packet長、部分出力、バッファを明示的に管理します。

例のマイクバッファは無音で、受信Byteも再生しません。仮実装のままでは録音による実時間の送信間隔もないので、実音声の送信にする際は時刻管理か取り込み周期を加えます。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
PCMFlowUDP EspToEspRaw starting
Local IP:
Ready
```

## 確認と問題の切り分け

UDPで生PCMのバイト列を交換することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
