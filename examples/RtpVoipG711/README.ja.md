# RtpVoipG711

> English: [README.md](README.md)

RTPでG.711を送信・受信して復号するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [RtpVoipG711.ino](RtpVoipG711.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<WiFi.h>`, `<WiFiUdp.h>`, `<PCMFlow.h>`, `<PCMFlowUDP.h>`, `<PCMFlowG711.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

RTPでG.711を送信・受信して復号する例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `g_udp.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `g_audio.setOutputFormat(...)` — 入力形式だけでなく、次の段階が受け取れる形式を選びます。
3. `g_audio.setInputSource(...)` — パイプラインが読む間ずっと有効なSourceを接続します。
4. `g_enc.encode(...)` — 十分な領域へ符号化し、結果を確認してから出力を使います。
5. `g_receiver.poll(...)` — 保留入力を定期的に処理し、結果を確認してから新しい値を使います。
6. `g_dec.decode(...)` — 符号化された入力の長さと形式を確認してから復号結果を使います。
7. `g_audio.pump()` — 復号／変換を進め、得られたPCM フレームだけを取り出します。

変更する前に確認する定数: `kRemoteIp`, `kRemotePort`, `kLocalPort`, `kSampleRate`, `kSamplesPerPacket`, `kSsrc`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

ローカルWi-Fi情報と相手のIP／ポートを設定します。UDP Socketを開始してからプロトコルの送受信を始め、受信は定期的にpollします。Raw UDP・VBAN・RTPは区切りや形式が異なるので双方を合わせます。

UDPに配送・順序・再送の保証はなく、送信結果は再生確認ではありません。これらの例にはマイク／スピーカーの仮実装があるため、無音の送信や受信byte数だけでは実音声を確認できません。サンプル／バイトの単位と送信間隔を保って実機入出力へ置き換えます。

RTP時刻はPayloadのクロックに従い、全コーデックがPCMの周波数と同じとは限りません（G.722など）。Packet長、部分出力、バッファを明示的に管理します。

この例はマイクの代わりに0を送り、受信Decoderをpumpしますが、PCMを取り出して設定済みスピーカーへ渡す処理はありません。録音と、PCMの取り出し／出力の両方を加えます。RTP SocketだけではSIP発呼やSDP交渉は行いません。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text

Ready
```

## 確認と問題の切り分け

RTPでG.711を送信・受信して復号することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
